# 困ったとき

最初に npm run doctor を実行してください。ログは .dots-bridge/logs/ にあります。
問い合わせにトークン、発言本文、音声、ログ全体を貼らないでください。失敗した段階とエラー名を伝えてください。

| 症状 | 確認するところ |
| --- | --- |
| Macにつながらない | スマホとMacのLAN/VPN、setupのホスト、G2パッケージとスマホの接続設定 |
| ポートが使用中と出る | 手動と常駐を二重起動していないか。別アプリが同じポートを使う場合はsetupの --port を変更 |
| 認証に失敗する | npm run token で自分のトークンを確認。URLだけ変更しても認証できない |
| Chromeが未接続 | build/extension を導入したか、通常タブか、設定したDot URLか、Dotタブを再読み込みしたか |
| 通話ボタンが動かない | Dotの電話機能が利用できるか。設定したDotの通常タブを開く |
| 音声入力が届かない | ChromeのマイクがBlackHole 2chか、G2マイクの許可、PTTが録音中か |
| 通話の返答が無音 | Macの音声収録許可とヘルパーの再起動、スマホの音声オン、出力先 |
| 画面オフ側の長押しで電話に戻したのに始まらない | モード切替だけでは発信しない。「通話を始める」か点灯中の通常操作側／R1長押しを使う |
| 長押しが録音にならない | 消灯中は接続済み通話のPTTだけ。タップ直後の長押しはメニュー操作。接続復旧中は復旧後に押し直す |
| Macが音声ヘルパーをブロックする | 実行用セットはアドホック署名。配布元とチェックサムを確認したうえで、システム設定 → プライバシーとセキュリティの「このまま開く」で対象アプリを許可し再実行。詳細は [Appleの説明](https://support.apple.com/en-us/102445)。ソースからのビルドも可能 |
| ASRが使えない | macOS 26以上、Appleの対応ハードウェア・言語、doctorの音声認識の結果 |
| 新しい発言を送れない | 前の発言が queued / processing / uncertain のまま残っていないか |
| package_id taken | 自分の一意のIDを --package-id で指定してG2パッケージを作り直す |
| ASR結果から進まない | 送信確認がオンならメニューまたはスマホの「Dotに送信」を選ぶ |

## 「結果不明」で止まった場合

ブリッジは、Dotに届いたか不明な発言を自動で再送しません。
同じrequestIdで message/read を使い、結果を照会してください。
外部アプリに「結果を確認」「Macで確認して次へ進む」がある場合、Dotの画面で元の入力と返答を確認してから進めます。
音声認識の表示が出ても、その後の送信が前の未確認発言で止まる場合があります。

## Chrome側の制約

入力欄に自分の下書きがあると、その内容を上書きせず送信を拒否します。
ブリッジの返答待ち中に同じDotへ別の入力を送ると、返答との対応が分からなくなる場合があります。
バックグラウンドのタブ、隠れた／最小化されたウインドウ、Macのスリープで返答検出や通知が遅れる場合があります。
初めての動作確認ではDotを選択した通常タブを開いておいてください。
ChatGPT画面の構造が変わった場合は、Chrome拡張の対応が必要です。

## 録音開始まで時間がかかる

スマホの「PTT開始の診断」で遅い段階を確認します。「処理キュー」はアプリ内の開始待ち、「通話・音声準備」は通話開始や再生準備、「ブリッジ入力許可」はMacの応答待ち、「G2マイク開始」は共有マイクの切替とEven Appの応答待ちです。長押しがアプリに届くまでの時間は含みません。

アプリは長文のページ分割を再利用し、閉じた履歴一覧やマイク切替中のキャラを描画しません。録音表示は実際のマイク開始を待って切り替わります。遅延が続く場合は、利用モードと各段階の時間を確認してください。
